## [0.8.0] — 2026-10-08

### Безопасность (главное — сервер смотрит наружу)
- **WAN-hardening туннельного порта (`internal/hardening`)**: первый байт
  соединения — не TLS ClientHello (0x16)? Это сканер (nmap -sV, masscan,
  пробники бинаря): **tarpit + тихое закрытие БЕЗ единого байта ответа** —
  приложение не палится (нет баннеров/версий/HTTP-страниц). Глобальный и
  per-IP лимиты параллельных соединений против автоматизированного скана;
  счётчики `reverseray_hardening_*` в `/metrics` и `/status` (без IP).
- **Panic-safety**: ни одна горутина с недоверенным вводом не роняет процесс
  (tunnel/inbound/admin — recover со стеком в лог, наружу — без-деталей 500);
  slowloris-гвард инбокса (первый запрос ≤ 30 с).
- **Security-заголовки** на всех admin-эндпоинтах; тексты ошибок наружу не
  утекают (reload-ошибки — только в лог).
- **mtproto2 — канон MTProto 2.0**: официальный dh_prime Telegram (safe prime,
  вшит «known good» по рекомендации самих guidelines); валидация долей пира
  1 < g < p−1 + коридор [2^1984, p−2^1984]; auth_key = 256 Б g_ab;
  msg_key = SHA256(auth_key[88+x…][+pt])[8:24]; AES-256-IGE; конверт
  [key_id 8][msg_key 16][IGE]; msg_id чётный клиент→сервер / нечётный
  сервер→клиент; паддинг 16..31 (проверка канона 12..1024 при расшифровке).
  Приватный хендшейк ReverseRay (TLS+SPKI-pin+HMAC) остаётся входной точкой,
  ключи DATA/UDP_DATA перегенерируются DH-апгрейдом после READY
  (KEY_REQ 0x24 / KEY_RESP 0x25); управляющие кадры не шифруются.
- **Аудит buffer overflow/injection** — новый отчёт
  `docs/security-audit-2026-10.md`: лимиты кадров, WS 1 МБ cap, SOCKS/HTTP
  длины, DNS-метки 255, JSON-глубина, паник-гварды; Go-память безопасна,
  фаззинг-стиль тесты на декодеры.

### Добавлено
- **Модульная система APK ↔ сервер (`modules/`)**: общий манифест
  `modules/modules.json` (schema 1) — реестр протоколов + политика; обе
  стороны парсят его одинаковыми правилами (Go `internal/modules`, Kotlin
  `core/Modules.kt`); **APK — тонкий движок как ПО POS-машин**: логика
  обновляется с GitHub без переустановки; скачивание только при изменении
  версии/хеша, раз в сутки (`RR_MODULES_CHECK_HOURS`), мусорный манифест
  НИКОГДА не применяется (фоллбек на встроенный), даунгрейд запрещён;
  сервер применяет реестр на горячую, сохраняет в state/modules.json.
- **Протокол mtproto2 в согласовании**: динамический реестр
  (`rrp.SetRegistry`; rrp1 — фундамент всегда), обмен списками в
  HELLO/HELLO_OK/READY; старые стороны автоматически фоллбечатся на общий.
- **Лимит трафика — КОРОЛЬ**: исчерпан → ровно ноль байт (туннель останавливается
  полностью), на главном экране сообщение, при нажатии Старт/Реконнект —
  отдельное окно «Траффик закончился» с датой обновления лимита; кнопка
  «Ждать сброса и подключить» включает автоподключение.
- **Автоподключение (выкл по умолчанию)**: коннект при открытии приложения;
  при достигнутом лимите — ожидание даты сброса (проверка раз в минуту),
  реконнект только после него.
- **Спидтест 5 секунд** после подключения — только если лимит не достигнут;
  результат в окне статуса главной.
- **Единое консольное окно (`StatusConsole`)** на Главной/Обновлении/Логе:
  листается, кнопка «↧ live» внутри бара (авто-прокрутка возвращается по
  клику), положение сохраняется при переключении вкладок; цветовые роли
  строк: зелёный — поднялся, красный — упал, тёмно-жёлтый — важное,
  белый — информационная беготня.
- **Вкладка «Лог»**: полный журнал сервиса + «Копировать весь лог» +
  «Поделиться».
- **Честные вкладки**: «О приложении» (версия/код, версия модулей, RAM,
  диск APK+данные, **трафик за всё время**, текущий протокол); «О устройстве»
  (+ модель CPU, общая RAM, SDK, Java VM); «О сети» — ВСЁ, что приложение
  узнало: DNS-серверы, **кто реально резолвит** (TXT-проба сквозь роутер,
  `DnsProbe`), DNSSEC (AD-флаг), DoT (853), DoH, ECS («приложение не шлёт»),
  шифрование SNI («не поддерживается уровнем ОС»). Канон: мы не прячем
  ничего из собранного.
- **Ссылка без кнопок-костылей**: вставил — приложение само починило,
  показало зелёное «Ссылка сохранена ✓» и тост; «Очистить» — с
  подтверждением; кнопка «Проверить и починить» удалена (авто).
- **Поделиться приложением**: ссылка на GitHub или APK «в сборе» — без
  настроек/токенов/логов (у нового пользователя всё в дефолтах).
- **Спидтест/лимит в compose/rr.sh**: env `RR_HARDENING*`, `RR_MODULES_*`,
  `RR_RESTART_DELAY`/`RR_RESTART_MAX`.

## [0.7.4] — 2026-10-08

### Исправлено (ГЛАВНОЕ — «ERROR 2: protocol error» на проде 81.25.59.194:4433)
- **HELLO с `ver` числом ронял рукопожатие**: APK 0.7.3 слал `"ver":1`
  (число), а Go-сервер ждёт строку → `json.Unmarshal` падал → `bad HELLO`
  → ERROR 2 «protocol error». Воспроизведено live-тестом с прод-сервером;
  канон **`"ver":"1"`** (строка в кавычках) подтверждён и для новых, и для
  старых серверов. Сервер, в свою очередь, стал **толерантным** (FlexString):
  принимает и число, и строку — старые APK не сломаются.
- **AUTH с HMAC в std-base64 падал с «auth failed»**: APK кодировал HMAC
  стандартным base64 (`+/` и `=`), сервер декодировал только base64url.
  Канон — **base64url без паддинга**; сервер принимает все три кодировки
  (constant-time сравнение сохранено).
- Введён регресс-тест `TestHandshakeToleratesApk073Format` и live-скрипт:
  канонический обмен APK ↔ прод-сервер проверен до READY + PONG.

### Добавлено
- **Мульти-протокол с согласованием** (архитектура под много протоколов):
  реестр `server/internal/rrp/protocol.go` + `RrpProtocols.kt`; клиент и сервер
  обмениваются `proto`/`protocols` в HELLO/HELLO_OK/READY; мусорное/пустое
  значение сводится к дефолту **без ошибки**; дефолт сервера задаётся
  `RR_PROTOCOL` (compose/env, `RR_DEFAULT_PROTOCOL` тоже работает).
- **PROBE-валидация реального трафика (кадр 0x23)**: при смене протокола
  сервер диалит реальный хост (по умолчанию `1.1.1.1:443`, настраивается в
  настройках APK) и отвечает фактом egress. Смена протокола коммитится
  (сохраняется ссылка и выбор) **только после** READY + PROBE; при неудаче —
  3 ретрая по 5 с и мгновенный откат UI на последний рабочий протокол,
  cooldown 60 с — защиты от rate-limit циклов.
- **Бронепарсер rrp:// ссылок** (`RrpUri.sanitizeLink`): сам чинит мусор —
  текст вокруг ссылки, невидимые ASCII/Unicode (контрольные, zero-width,
  bidi, NBSP), кавычки всех видов (`" ' ` « » „ “ ‘ ’`), декоративные обёртки
  (`< > ( ) [ ] { }`), хвостовые точки/запятые; ссылка теперь несёт `proto=`
  всегда явно (и сервер, и APK парсят её без догадок).
- **Приложение: 4 вкладки** — Главная (круглая Старт/Стоп, окно трафика со
  скоростью, счётчиками пакетов «стрелками», типом/размером последнего
  пакета, внешним и локальным IP, страной/оператором, коротким
  терминальным логом), Связь (ссылка+QR+файлы+смена протокола), Обновление
  (версия, авто-проверка раз в 24 ч с закрываемым окном, тех-лог обновления
  в терминальном окне), Настройки («О телефоне»-панель: модель/Android/
  билд/патч/ядро/экран/память, лимит трафика, только-Wi-Fi, PROBE-цель,
  LAN).
- **Лимит трафика**: по умолчанию без ограничений; опционально сумма вход+выход
  за сутки или месяц с днём сброса; превышение останавливает туннель со
  статусом; счётчик переживает рестарт; кнопка сброса.
- **Только по Wi-Fi**: туннель не поднимается в мобильной сети и стартует сам
  при появлении Wi-Fi.
- **Логи настроек**: изменённые настройки пишутся в статус-лог ТОЛЬКО при
  фактическом изменении значения.
- **Веб-морда сервера `/ui`** (read-only, без зависимостей, авто-обновление
  3 с): сессии с протоколом/RTT/байтами, счётчики, egress IP сервера;
  `/status` — JSON для скриптов; скейлится от старых телефонов до
  ультрашироких мониторов. `rr.sh` печатает LAN-URL (`http://IP:9090/ui`)
  и по умолчанию открывает админ-порт в LAN (`--no-ui` возвращает localhost).
- Тестов: **63 Go** + **101 Kotlin/JVM** (было 84): канон HELLO/AUTH в обоих
  направлениях, толерантность форматов, согласование протоколов, PROBE,
  бронепарсер, лимиты трафика (unit), Android API 21/31 (Robolectric).

## [0.7.3] — 2026-10-08

### Исправлено (ГЛАВНОЕ — туннель наконец-то подключается)
- **«сервер вернул ERROR 2: protocol error» навсегда**: клиент в HELLO
  **не отправлял обязательное поле `device`** — сервер отвергал рукопожатие.
  Теперь клиент шлёт `device` (имя из конфига, phone-1 по умолчанию).
- **AUTH по неправильному nonce**: клиент генерировал СВОЙ nonce и игнорировал
  nonce из HELLO_OK — сервер сверяет HMAC со своим, аутентификация падала бы
  следующим слоем. Теперь клиент HMAC-ит **серверный** nonce (как в спецификации).
- Anti-replay реально работает: сервер «сжигает» nonce (TakeNonce) до проверки.
- Флаги стран показывались как «XX»: эмодзи-флаги не рендерятся на Android —
  теперь в APK вбилжены PNG-флаги 200 стран (res/drawable-nodpi, 804К).
- rr.sh печатал строку подключения с ведущим пробелом — убран, строка чистая.

### Добавлено
- Скрипт установки и лог сервера печатают **два блока**: строку подключения
  для APK и готовый **outbound для Xray** (address = LAN-IP хоста из локальной
  сети, не IP докер-бриджа — rr.sh определяет его сам).
- Пример docker-компоуза: прокси по умолчанию **без пароля** (HTTP+SOCKS5),
  авторизация опционально через `RR_AUTH_USERNAME`/`RR_AUTH_PASSWORD`.
- Расширенные логи приложения: SENT/RECV HELLO/AUTH/READY с полями, raw-дамп
  payload'а ERROR-кадров — для анализа прямо из «Журнала».
- Статус в GUI: ERROR держится ≥1.5 с (не мигает), а RETRY показывает и
  последнюю ошибку: «переподключение через N с — последняя ошибка: …».

## [0.7.1] — 2026-10-08

### Исправлено
- **Crash-loop «bootstrap: write tokens: permission denied» навсегда** (прод-деплой
  на Portainer): контейнер nonroot (65532) не мог писать в root-owned
  bind-mount `./state`.
  - compose: контейнер работает под root **без capabilities** (`user: "0:0"`,
    `cap_drop: ALL` остаётся) — запись в state работает на любом host-каталоге,
    `chown` не нужен. Hardening-путь (`65532` + chown) задокументирован.
  - Сервер больше не падает от недоступного state: токены и PKI регистрируются
    **в памяти**, в лог печатается готовая `rrp://` строка с токеном —
    подключение работает сразу; `tokens.json`/PKI дописываются автоматически,
    как только каталог становится записываемым (самовосстановление).
  - Dockerfile: `/var/lib/reverseray` в образе с владельцем 65532 (named
    volume получает права автоматически).
- Регресс-тесты: read-only state dir → сервер стартует (serverapp), PKI
  помечается ephemeral (tlscert).

## [0.7.0] — 2026-10-08

### Добавлено
- **UDP через туннель** (перенесено из v1.0): SOCKS5 UDP ASSOCIATE (cmd 0x03),
  кадры RRP `UDP_ASSOC`/`UDP_DATA`, DNS+ (порт 53) и QUIC-проход через телефон.
  В compose публикуется 1080/udp; SSRF-guard действует (порт 53 — разрешён).
- **WebSocket-транспорт RRP** (`transport=ws`): тот же TLS-порт 4433, апгрейд
  RFC 6455 `/rrp` — обход DPI-ограничений портов (443/80/CDN). Сырой RRP/1
  работает как раньше, один порт обслуживает оба транспорта.
- **График трафика в приложении**: реалтайм (байт/с, окно 60 с) в статус-карточке.
- **Экспорт/импорт конфигурации файлом** (SAF, API 19+; на 14–18 скрыто).
- **Деплой одной командой из любого каталога**: `deploy/install.sh` создаёт
  `./reverseray/` (compose + state + .env + инструкция) относительно текущей папки.
- Rate-limit рукопожатий смягчён: 120/мин/IP (было 60), настраивается
  `RR_LIMITS_HANDSHAKES_PER_MIN`; lockout остался только за невалидный HMAC.
- CI: gitleaks-скан секретов, dependency-review для PR, валидация gradle-wrapper.

### Исправлено
- **«no such algorithm: SHA-512 for provider BC» навсегда**: TLS-крипто клиента
  переведено на BcTlsCrypto (lightweight, без JCA) — больше не зависит от
  урезанного платформенного провайдера "BC". Работает из коробки на всех
  Android 4.0+ (API 14+), включая те, где v0.5.1 не помогала.
- Гонка close/send в UDP-канале сессии (обнаружено race-детектором в тестах).
- Ответ SOCKS5-клиенту в UDP дополняется SOCKS-заголовком [RSV/FRAG] (RFC 1928).

### Производительность
- Release-пайплайн: паблиш больше не пересобирает бинарии (артефакты вместо
  дубль-сборки) — минус 3 джобы и ~5–8 минут на релиз.
- CI: Go-тесты и coverage в одном прогоне; кэш Gradle (`setup-gradle`);
  `concurrency: cancel-in-progress`; gradle build-cache/parallel.

### Изменено (UI)
- Главная кнопка **«Старт» — большая круглая (220dp), сверху**, под ней «Стоп»;
  шапка экрана — иконка приложения (баннер-заглушка убран).

## [0.3.1] — 2026-09-20

### Исправлено
- **APK из релиза не устанавливался**: публиковалась неподписанная сборка
  (`app-release-unsigned.apk`), Android отвергал её при установке.
  Теперь релизный APK подписан репозиторным ключом (v1+v2+v3 схемы) и
  устанавливается штатно на Android 4.0–16; обновления ставятся поверх
  предыдущих благодаря стабильной подписи.

### Безопасность
- Подпись APK: приоритет — секреты окружения (`RR_KEYSTORE*`); при их
  отсутствии используется открытый репозиторный ключ
  (`android/app/rr-release.keystore` + `signing.properties`).
  Он обеспечивает стабильность подписи, но не авторство: подлинность
  артефактов верифицируется по `SHA256SUMS` в GitHub Release.
- Владельцы, желающие публиковать APK под личным ключом, задают
  `RR_KEYSTORE*` в Secrets — подпись переключается автоматически.

## [0.3.0] — 2026-09-18

### Добавлено
- **Агрессивная среда (WAN) — постоянные функциональные тесты сервера**: oversized-кадры, неверная версия протокола, неизвестные типы кадров, обрезанные payload, мусор на портах туннеля и mixed, flood PING, параллельный мусор, брутфорс токена с проверкой lockout, отсутствие утечек секретов в `/metrics` и ответах admin API. Сервер обязан выживать и продолжать принимать клиентов.
- **Защитные тесты клиента против враждебного сервера**: настоящий TLS-сервер с известным пином, oversized/неверная версия → чистое закрытие; SSRF-блокировка приватных и TEST-NET адресов (кадр OPEN не покидает клиент); DATA на неизвестный поток → защитный CLOSE; внезапный обрыв → чистый переход в CLOSED.
- **Диагностика**: `RR_DEBUG_LOG=1` включает debug-логи сервера в тестах.

### Исправлено
- **Lockout-счётчик больше не лочит легитимных клиентов за NAT**: TLS-мусор и сканеры увеличивают только метрику; блокировка IP срабатывает исключительно при брутфорсе токена (5 невалидных HMAC).
- Rate-limit рукопожатий поднят с 10 до 60 в минуту на IP — 30 мусорных подключений больше не лишают доступа клиентов за общим NAT.
- SSRF-гвард: закрыты документационные диапазоны TEST-NET-1/2/3 (192.0.2/24, 198.51.100/24, 203.0.113/24).
- Баннер репозитория: минималистичный чёрный фон с текстом; генератор ассетов покрыт тестами и валидируется в CI (джоба `assets`).

## [0.2.1] — 2026-09-18

### Что нового
- **QR-код вместо ручного ввода.** Конфигурация считывается камерой; текущая
  конфигурация показывается QR-кодом для переноса на другое устройство
  (экран экспорта защищён от скриншотов).
- **Защита от подмены DNS.** Перед подключением приложение проверяет
  фактический IP-адрес назначения, а не только имя хоста: приватная сеть
  телефона остаётся закрытой даже при перенаправлении DNS.
- **Аудит безопасности.** По результатам внутреннего аудита устранены
  проблемы разной степени критичности; полный отчёт —
  [docs/security-audit-2026-09.md](docs/security-audit-2026-09.md).

### Надёжность
- Соединения больше не зависают при внезапной остановке сервера.
- Остановка туннеля происходит мгновенно, без ожидания сетевых таймаутов.
- Приложение корректно запускается на Android 4.0–16, включая уведомления
  и автозапуск после перезагрузки устройства.

### Для разработчиков
- 48 unit-тестов клиента (JUnit + Robolectric, API 21/31), тесты сервера
  с race-детектором, статический анализ gosec — критичных находок нет.
- Валидация бренд-ассетов включена в CI (`assets/brand/`).
- Сборка проверяется для amd64, arm64 и armv7.
