# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/); версионирование — [SemVer](https://semver.org/lang/ru/).

## [0.3.0] — 2026-09-18

### Добавлено
- **Агрессивная среда (WAN) — постоянные функциональные тесты сервера**: oversized-кадры, неверная версия протокола, неизвестные типы кадров, обрезанные payload, мусор на портах туннеля и mixed, flood PING, параллельный мусор, брутфорс токена с проверкой lockout, отсутствие утечек секретов в `/metrics` и ответах admin API. Сервер обязан выживать и продолжать принимать клиентов.
- **Защитные тесты клиента против враждебного сервера**: настоящий TLS-сервер с известным пином, oversized/неверная версия → чистое закрытие; SSRF-блокировка приватных и TEST-NET адресов (кадр OPEN не покидает клиент); DATA на неизвестный поток → защитный CLOSE; внезапный обрыв → чистый переход в CLOSED.
- **Диагностика**: `RR_DEBUG_LOG=1` включает debug-логи сервера в тестах.

### Исправлено
- **Lockout-счётчик больше не лочит легитимных клиентов за NAT**: TLS-мусор и сканеры увеличивают только метрику; блокировка IP срабатывает исключительно при брутфорсе токена (5 невалидных HMAC).
- Rate-limit рукопожатий поднят с 10 до 60 в минуту на IP — 30 мусорных подключений больше не лишают доступа клиентов за общим NAT.
- SSRF-гвард: закрыты документационные диапазоны TEST-NET-1/2/3 (192.0.2/24, 198.51.100/24, 203.0.113/24).
- Баннер репозитория: минималистичный чёрный фон с текстом; генератор ассетов покрыт тестами и валидируется в CI (джоба `assets`).

## [0.2.1] — 2026-09-18

### Что нового
- **QR-код вместо ручного ввода.** Конфигурация считывается камерой; текущая
  конфигурация показывается QR-кодом для переноса на другое устройство
  (экран экспорта защищён от скриншотов).
- **Защита от подмены DNS.** Перед подключением приложение проверяет
  фактический IP-адрес назначения, а не только имя хоста: приватная сеть
  телефона остаётся закрытой даже при перенаправлении DNS.
- **Аудит безопасности.** По результатам внутреннего аудита устранены
  проблемы разной степени критичности; полный отчёт —
  [docs/security-audit-2026-09.md](docs/security-audit-2026-09.md).

### Надёжность
- Соединения больше не зависают при внезапной остановке сервера.
- Остановка туннеля происходит мгновенно, без ожидания сетевых таймаутов.
- Приложение корректно запускается на Android 4.0–16, включая уведомления
  и автозапуск после перезагрузки устройства.

### Для разработчиков
- 48 unit-тестов клиента (JUnit + Robolectric, API 21/31), тесты сервера
  с race-детектором, статический анализ gosec — критичных находок нет.
- Валидация бренд-ассетов включена в CI (`assets/brand/`).
- Сборка проверяется для amd64, arm64 и armv7.

## [0.2.0] — 2026-09-18

### Добавлено
- Android-клиент: RRP/1 поверх TLS 1.3 (BouncyCastle), foreground-сервис, переподключение с экспоненциальной задержкой, реакция на смену сети, хранение конфигурации.
- Ядро протокола как pure-Kotlin модуль: кодек кадров с лимитами по типам, парсер адресов ATYP, SSRF-гвард, парсер конфигурационной строки `rrp://`.
- Сервер: admin API, метрики Prometheus, обработчик перечитывания токенов.
- Деплой: `compose.yaml` с digest-пином, `deploy/digests.yaml`, ререлиз-пайплайн с APK в GitHub Releases.
- Лендинг на GitHub Pages.

### Исправлено
- Дублирование реализации SSRF-гварда (унифицирована версия без DNS-резолва).
- Конфликт `minSdk` с зависимостью zxing (зависимость подключена с runtime-guard на уровне API 19).
- Конфликт META-INF-манифестов BouncyCastle в APK.

## [0.1.0] — 2026-09-18

### Добавлено
- Первая работоспособная версия сервера: mixed SOCKS5/HTTP-инбокс, туннели RRP/1, аутентификация токенами (SHA-256 + HMAC), TLS 1.3 с SPKI-пином на CA, self-signed CA с ротацией leaf-сертификатов.
- Релизный пайплайн: бинарии linux amd64/arm64/armv7, SHA256SUMS, Docker-образ ghcr.io (multi-arch).
- CI: gofmt/vet/тесты с race-детектором, покрытие, smoke-сборка образа.
