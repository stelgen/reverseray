# Security Policy

## Threat model

| Угроза | Митигация |
|---|---|
| Открытый прокси | inbound auth (user/pass) + IP allowlist + rate-limit |
| MitM | TLS 1.3 + SPKI-pin (CA), ALPN обязателен, запрет downgrade; v0.8.1: строгий пин — несовпадение заданного пина = отказ соединения (чужим сертификатам не доверяем); TOFU только при первой дружбе (пина нет) |
| Replay аутентификации | одноразовый nonce (TTL 60 с) + HMAC-SHA256 |
| Кража хранилища токенов | сервер хранит только SHA256(token); HMAC-ключ = хэш |
| Толерантность кодировок HMAC (v0.7.4) | принимаются base64url/std — это ОДНИ И ТЕ ЖЕ байты; сравнение constant-time, безопасность не ослаблена |
| SSRF в домашнюю сеть телефона | блэклист приватных диапазонов на клиенте (по умолч. on) |
| OOM/DoS сервера | frame-limits по типам, окно 512КБ/стрим, бюджет 16МБ/устройство, max streams |
| Брутфорс AUTH | 10 handshakes/min/IP, lockout 30с·2^n до 10 мин |
| Утечка приватности в логах | хосты назначения не логируются (redaction default) |
| Подмена APK | подпись релиза v1+v2+v3 + SHA256SUMS + fingerprint в README; v0.8.1: апдейтер сверяет скачанный APK с SHA256SUMS и отменяет установку при несовпадении |
| Компрометация телефона | per-device токены, revoke, kick, ротация CA через re-enroll |
| Скан порта / пробив бинаря (v0.8) | WAN-hardening: первый байт ≠ TLS → tarpit + тихое закрытие, НОЛЬ ответных байтов (nmap -sV не видит сервиса); глобальный/per-IP лимиты параллельности; нет баннеров/версий/HTTP-страниц |
| Автоматизированный флуд/скан (v0.8) | лимиты параллельности (глобал + per-IP), rate-limit рукопожатий, метрики hardening (без IP) |
| Утечка деталей ошибок (v0.8) | паники/ошибки гасятся recover'ами; наружу — без-деталей 500/ERROR-кадры; security-заголовки на admin |
| Slowloris (v0.8) | дедлайн 30 с на первый запрос инбокса; 15 с на TLS/KEY-обмен |
| Крипто payload'а туннеля (v0.8, mtproto2) | канон MTProto 2.0: официальный dh_prime Telegram (safe prime), DH-валидация по Security Guidelines, AES-256-IGE, msg_key SHA-256, msg_id parity, анти-логжам-проверка p на клиенте; поверх приватного хендшейка (TLS+HMAC) |
| Подмена манифеста модулей (v0.8) | мусорный манифест НИКОГДА не применяется (фоллбек), даунгрейд запрещён, скачивание только при изменении версии/хеша; rrp1 — фундамент всегда |
| Телеметрия/внешние хосты (v0.8) | запрещены каноном; privacy-audit робот в CI держит белый список хостов |
| Plaintext-трафик (v0.8.1) | туннель — только TLS 1.3 (MinVersion); апдейтер/спидтест/NetInfo/DoH-проба — только https; privacy-audit блокирует http:// вне loopback |
| Подмена пакетов/внедрение в туннель (v0.8.1) | TLS 1.3 AEAD (целостность+аутентификация каждого байта); в mtproto2 — воспроизведение msg_key + auth_key_id + salt/session_id, чужой конверт = закрытие сессии; лимиты кадров отсекают переполнения; nonce TTL 60 с отсекает replay рукопожатия |
| Амплификация через камуфляж (v0.8.2) | NOISE-кадры ≤ 4096 Б (лимит контрольных кадров); ответы сервера — не больше 30/мин на сессию (rate-limit в сессии); мусорный/битый NOISE не рвёт сессию (DoS-вектор закрыт); камуфляж включается только манифестом и только для авторизованных сессий |
| Ложное чувство «VPN для зла» (v0.8.2) | API Mask — это форма трафика, а не анонимность: трафик по-прежнему идёт с резидентного IP владельца и подчиняется ответственности владельца (см. «Ответственность»); модуль не скрывает ничего от самого владельца — весь шум виден в консоли и метриках |

## Уровень хоста (ICMP/SYN) — v0.8

ICMP-пинги и SYN-сканы отвечает ЯДРО хоста — приложение на это бессильно.
Рецепт (опционально, по желанию владельца):

```bash
# ограничить ICMP echo: 30/мин, остальное молча дропать
sudo iptables -A INPUT -p icmp --icmp-type echo-request -m limit --limit 30/min -j ACCEPT
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j DROP
```

Приложение же гарантирует: после установки TCP-соединения любой не-TLS
клиент получает тишину (tarpit + тихое закрытие).

## Криптомодель mtproto2 (v0.8)

- Вход — приватный хендшейк ReverseRay (TLS 1.3 + SPKI-pin + HMAC-токен).
- После READY стороны договариваются о свежих ключах: DH на официальном
  dh_prime Telegram (safe prime; p и (p−1)/2 простые — проверено тестом),
  g=3 (p mod 3 = 2 — канон quadratic reciprocity), приватные доли 2048 бит.
- Валидация долей пира — канон Security Guidelines: 1 < g_peer < p−1 и
  коридор [2^1984, p − 2^1984]; клиент ДОПОЛНИТЕЛЬНО сверяет p байт-в-байт
  (anti-logjam).
- auth_key = 256 Б (g_ab); auth_key_id = SHA1(auth_key)[0:8] (маркер);
  msg_key = SHA256(auth_key[88+x:120+x] ‖ plaintext)[8:24];
  AES-256-IGE поверх ECB (одинаковая реализация в Go и Kotlin).
- msg_id: чётные клиент→сервер, нечётные сервер→клиент (канон); паддинг
  16..31 Б; при расшифровке проверяется 12..1024 и msg_key (целостность).
- Управляющие кадры (PING/WINDOW/CLOSE/OPEN/PROBE/KEY_*) не шифруются —
  они не содержат пользовательских данных.
- Кросс-языковой KAT: Go-сервер шифрует, Kotlin-тест расшифровывает и
  наоборот (MtProtoKATTest ↔ katgen_test.go).

## Дисциплина ресурсов (v0.8)

- счётчики трафика — в RAM, запись на диск раз в минуту;
- Docker: restart-governor (мин. пауза 30 с; 20 падений подряд → контейнер
  умирает с ошибкой), healthcheck обязателен, pids_limit, read-only rootfs;
- APK: без wakeup-молотилки, бэкграунд-проб (только спидтест 5 с после
  коннекта и DNS-проба при открытии «О сети»).

## Ответственность

Весь egress-трафик идёт с резидентного IP телефона. Владелец телефона отвечает
за исходящий трафик. Используй per-device токены и мгновенный revoke.

## Хранение секретов на сервере

- `state/` — 0700; `ca.key`, `leaf*.key` — 0600. С v0.7.1 контейнер по умолчанию
  работает под root **без capabilities** (`cap_drop: ALL`, no-new-privileges,
  read-only rootfs, distroless) — иначе nonroot-пользователь не может писать в
  root-owned bind-mount (класс ошибок «permission denied»). Hardening: `user: 65532:65532` + `chown -R 65532:65532 state`.
- Токены — только хэши. Бэкап `state/` перед апгрейдом (см. README deploy).

## Подпись APK

Релизный APK подписан схемами v1+v2+v3. Ключ: `android/app/rr-release.keystore`
(пароли — в `android/app/signing.properties`, файлы публичны). Стабильная
подпись гарантирует установку обновлений поверх предыдущих версий; авторство
артефактов верифицируется по `SHA256SUMS` GitHub Release. Владелец может
заменить ключ через секреты `RR_KEYSTORE*` в настройках репозитория.
