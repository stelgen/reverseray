# Workflow

Процесс разработки и релизов (шаблон — nextgen-воркфлоу).

## Ветки

| Ветка | Назначение | Правила |
|---|---|---|
| `main` | прод-код | защищена, только PR; fast-forward |
| `gh-pages` | лендинг | только деплой-джоба/ключ |
| `fix/*`, `feat/*` | работа | PR в main |

## Коммиты

Conventional Commits: `feat:`, `fix:`, `docs:`, `ci:`, `test:`, `chore:`, `style:`.

## CI-гейты (обязательные к merge)

| Джоба | Содержание |
|---|---|
| Go test/vet/fmt | gofmt, vet, `test -race`, coverage |
| Android build | assembleDebug + unit-тесты (Robolectric 21/31, JVM-изоляция, i18n-гейты) |
| Docker run | сборка образа → запуск КАК В ПРОДЕ (родной entrypoint) → healthcheck до 90 с → compose-smoke на родном compose.yaml; упал/не healthy → красный прогон с docker logs+inspect |
| Brand assets | перегенерация + сверка с закоммиченным (+ живой banner.gif, скриншот приложения) |
| Gitleaks | скан секретов (каждый push/PR) |
| Dependency review | гейт уязвимых зависимостей на PR |
| Modules integrity | канон-чек `modules/modules.json` + тесты парсеров обеих сторон (Go+Kotlin) |
| Privacy audit | `scripts/privacy_audit.py`: ни телеметрии, ни внешних хостов вне белого списка, ни приватных данных/токенов в доках |
| Govulncheck | известные уязвимости stdlib/зависимостей |
| Screenshot bots | ДВА полностью независимых воркфлоу, асинхронно ПОСЛЕ релиза (workflow_run Release=success + cron + dispatch), НИКОГДА не блокируют релиз и друг друга: `screenshot-apk.yml` — JVM-рендер MainActivity (Robolectric NATIVE graphics, эмулятор удалён) → `assets/brand/screenshot.png`; `screenshot-web.yml` — веб-панель /ui из ОПУБЛИКОВАННОГО образа релиза (headless-chromium) → `assets/brand/web.png`; каждый коммитит только свой файл |
| CodeQL | стат-анализ безопасности |

## Политики тулчейна

| Политика | Правило |
|---|---|
| Пин Go | патч-версия Go пиннится РУКАМИ (сейчас 1.27.2) во всех go-джобах CI/release — govulncheck и тайминговые тесты видят ровно тот тулчейн, что проверен локально; бамп патча — координированный коммит. govulncheck — пиннутая версия + retry ×3 |
| Диагностика фейлов | упавший шаг обязан оставить артефакт/step-summary с причиной (логи джоб без токена нечитаемы) |

## Политики канона

| Канон | Правило |
|---|---|
| Android 4.0 (API 14) | компонента, противоречащая совместимости, отменяется или переписывается, ЕСЛИ не требует большого оверхеда; иначе — тех-долг. Не городим кастом ради кастратных сборок |
| Лимит трафика — король | достигнут → РОВНО НОЛЬ байт от APK; окно на Старт/Реконнект; авто-реконнект ждёт дату сброса |
| Приватность: ничего не прячем | всё, что делают с сетью и данными юзера, видно в консоли и «О сети»; privacy-audit блокирует телеметрию и внешние хосты вне белого списка |
| Скрытие порта | WAN-hardening: сканер не получает ни байта (tarpit+тишина); отключение — только осознанно (`RR_HARDENING=false`) |
| Дисциплина SSD/RAM | счётчики в RAM, на диск — раз в минуту |
| Модули | APK — тонкий движок; общий манифест APK↔сервер; обновление по версии/хешу; мусор не применяется. Слои: новый протокол подхватывается сервером (apply/dedup/no-downgrade) и старым движком (мусор → rrp1); релиз движка и манифеста независимы |
| Версии протоколов | каждый протокол несёт публичную `ver`, пробрасывается во весь стек (GUI, /status, /ui); нет версии — нигде не показываем |
| Строгий пин / анти-MITM | пин = SHA256(SPKI CA = последний серт цепочки) у обеих сторон; не совпал → отказ + ЯВНОЕ подтверждение владельца (RrpUri.replacePin); TOFU — только первая дружба; листы 3 года, пин от ротации листа не меняется (KAT RrpPinTest) |
| Фоллбек протоколов | откатывается ТОЛЬКО клиент (3 неудачи → rrp1, запись в журнал); сервер не откатывается никогда |
| Апдейтер | APK сверяется с SHA256SUMS релиза; несовпадение — установка отменяется |
| API Mask | шум ходит ТОЛЬКО внутри туннеля; суточный бюджет из манифеста; байты шума — в счётчик трафика; клиент шлёт NOISE только при подтверждённой сервером возможности. Свои ~200 строк без зависимостей |
| AUTO-протокол | пустой `proto=` = AUTO: клиент просит предпочтительный, сервер согласует вниз до rrp1; явный `proto=` приоритетен; serialize пишет proto= ТОЛЬКО явно; встроенные протоколы известны всегда (isKnown ⊇ BUNDLED) |
| WireGuard — настоящий канон | актуальный WG whitepaper (Noise_IKpsk2, blake2s/curve25519/chacha20poly1305, mac1, TAI64N, sliding-window 2048); PSK = SHA256(token); любой крипто-протокол обязан иметь кросс-языковой KAT Go↔Kotlin байт-в-байт и e2e через настоящий rrp.Session |
| Выбор модуля клиентом — персистентен на сервере | кадр 0x2A CAM_CTL: сервер хранит выбор в state/camouflage.json; переживает офлайн; выключенный клиентом apimask сам не включается; мусорный кадр не рвёт сессию |
| Порядок блокировок RRP | `st.mu → s.mu` и НИКОГДА наоборот; `markClosed` не вызывается под `s.mu` |
| Flow-control | кредит ≤ буферу приёма: `tunnel_window = StreamWindow×2` (capIn 1 МБ); fake-phone в e2e уважает окно как настоящий APK |
| auth failed ≠ сетевой сбой | ERROR 1 = токен/ссылка устарели: авто-реконнект СТОП, честный статус + подсказка, токен-префикс (6 симв.) в журнале AUTH. Ретраи запрещены: 5 неудач → IP-локаут 30с·2ⁿ (до 10 мин), клиент видит его как TLS handshake_failure(40) |
| Скриншот-боты: гейты до циклов | ошибка avdmanager/окружения не глотается — артефакт-диагностика; веб-бот стартует контейнер с `RR_LISTEN_ADMIN_TCP=:9090` (дефолт 127.0.0.1 рвёт хост-коннекты) |
| UX-канон GUI | любая вкладка APK скроллится (портрет/ландшафт/крупные шрифты); журнал обновлений — единая консоль, на языке приложения; никаких «пустых полей» и скобок-пояснений |
| Кнопка Старт — состояния | Старт/Стоп — синяя; подключение — тёмно-жёлтая «Подключение»; ошибка — красная «Ошибка»; цветовые роли логов едины (info/warn/error) |
| Дашборд /ui | только техника: RT-график + карточки клиентов; «Константы защиты» — в APK и /status.json |
| Многоязычность | дефолт-ресурсы EN, RU — values-ru; выбор языка применяется без перезапуска; core-сообщения — каталог `Msgs`; новый код обязан добавлять строки — StringsParityTest/StringsGateTest падают перед деплоем |
| Governor без шелла | distroless без интерпретаторов: рестарт-губернатор — подкоманда бинаря (`reverseray governor`) |

## Тех-долг (бэклог)

- Android 4.0 (API 14–20): полный паритет UX (тинты/анимации Material 21+) — приоритет низкий.
- Эмуляторные (instrumentation) тесты APK в CI.
- cosign-подписи релизов + SBOM для APK.

## Спидтест-методика

1. 3 запуска подряд на стабильном линке, берём **медиану**.
2. Фиксируем: download/up Mbps, RTT (из PONG), окно графика (avg/peak).
3. Регрессия не ниже baseline предыдущего релиза −10%; адаптивный keepalive (20–55 с из RTT) не создаёт фонового шума.
4. Окна по умолчанию (512 КБ → 4 МБ max) достаточны для 100 Мбит/с при RTT ≤ 100 мс — менять без замеров запрещено.

## Релизы

1. Тег `vX.Y.Z` → `release.yml`: test → build-binaries (amd64/arm64/armv7) → docker (multi-arch, SBOM/provenance) → build-apk (подпись) → publish (SHA256SUMS + Release, тело из CHANGELOG).
2. Версионирование: SemVer; versionCode в `android/app/build.gradle.kts` растёт на каждый релиз.
3. Деплой-эквивалент прод-машины: `/portainer/Files/AppData/Config/reverseray/reverseray`.
4. Откат: предыдущий digest из `deploy/digests.yaml`.
5. Автообновление контейнера запрещено; обновления — вручную или автопилотом `deploy/rr.sh` (создаёт `./reverseray/`, решает установка/обновление, печатает строку подключения; `--reset` — обнулить состояние).
6. Паблиш берёт артефакты `build-binaries` (без пересборки); кэш Gradle в CI.

## Тестовые матрицы

- **Go**: unit + E2E (fake-phone) + hostile-environment (`evilclient_test.go`) + многоканальность (`multistream_test.go`: 8 потоков × SHA-целостность) — в каждом PR и релизе.
- **Android**: unit (Robolectric API 21/31, evil-сервер, QR, SSRF, тайминги, канон HELLO/AUTH, бронепарсер rrp://, согласование протоколов, PROBE); JVM-изоляция (`forkEvery=1`) обязательна.
- **Ассеты**: детерминизм, размеры, синхронность лендинг-копий.

## Диагностика

- Сервер: `RR_DEBUG_LOG=1`; admin `/metrics`.
- Клиент: кнопка «Журнал» — копируемая история ошибок.
- Артефакт `android-test-reports` в CI (always).

## Секреты

- `RR_KEYSTORE*` (GitHub Secrets) — личная подпись APK; по умолчанию репозиторный ключ.
- Deploy key — только gh-pages/теги; ротация 12 мес.
- В репо секретов нет (gitleaks в CI).
