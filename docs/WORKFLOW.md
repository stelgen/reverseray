# Workflow

Процесс разработки и релизов (шаблон — nextgen-воркфлоу).

## Ветки

| Ветка | Назначение | Правила |
|---|---|---|
| `main` | прод-код | защищена, только PR; fast-forward |
| `gh-pages` | лендинг | только деплой-джоба/ключ |
| `fix/*`, `feat/*` | работа | PR в main |

## Коммиты

Conventional Commits: `feat:`, `fix:`, `docs:`, `ci:`, `test:`, `chore:`, `style:`.

## Политики тулчейна

| Политика | Правило |
|---|---|
| **Пин Go (v0.8.3)** | патч-версия Go пиннится РУКАМИ (сейчас 1.27.2) во всех go-джобах CI/release — govulncheck и тайминговые тесты должны видеть ровно тот тулчейн, что проверен локально; бамп патча — координированный коммит. govulncheck — пиннутая версия + retry ×3 (флейки vulndb/сети) |
| **Диагностика фейлов** | упавший шаг обязан оставить артефакт/step-summary с причиной (логи джоб без токена нечитаемы): compose-smoke-diag, govulncheck-log, screenshot-diagnostics |

## Политики канона (v0.8)

| Политика | Правило |
|---|---|
| **Android 4.0 (API 14)** | любая компонента/действие, противоречащее совместимости, отменяется или переписывается, ЕСЛИ не требует большого оверхеда; иначе — в бэклог/тех-долг с запоминанием (см. «Тех-долг»). Не городим горы кастомного кода ради кастратных сборок Android (проекторы и т.п.) — адекватно и гибко. |
| **Лимит трафика — король** | достигнут → РОВНО НОЛЬ байт от APK; окно на Старт/Реконнект + сообщение в статусе; авто-реконнект ждёт дату сброса. |
| **Приватность: ничего не прячем** | всё, что приложение/сервер делают с сетью и данными юзера, видно в консоли и на «О сети»; privacy-audit в CI блокирует телеметрию и внешние хосты вне белого списка. |
| **Скрытие порта** | WAN-hardening: сканер не получает ни байта (tarpit+тишина); отключение — только осознанно (`RR_HARDENING=false`). |
| **Дисциплина SSD/RAM** | счётчики живут в RAM, на диск — раз в минуту; APK не изнашивает телефон 24/7. |
| **Модули** | APK — тонкий движок; общий манифест APK↔сервер; обновление по версии/хешу; мусор не применяется. |
| **Версии протоколов (v0.8.1)** | каждый протокол реестра несёт публичную версию (`ver` в modules.json); она пробрасывается во весь стек: GUI-кнопки/статусы/логи APK и сервера, /status, /ui. Нет публичной версии — поле пустое, нигде не показываем. |
| **Строгий пин / анти-MITM (v0.9.0)** | пин = SHA256(SPKI CA = ПОСЛЕДНИЙ серт цепочки) У ОБОИХ СТОРОН (клиент до 0.9.0 хешировал лист — ломалось при плановой ротации листа); заданный пин не совпал → отказ + диалог ЯВНОГО подтверждения владельца («Принять новый пин» → RrpUri.replacePin → реконнект); TOFU — только первая дружба (пина нет); молчаливого доверия нет никогда. Листы — 3 года, перевыпуск заранее, пин от ротации листа НЕ меняется (KAT RrpPinTest). |
| **Фоллбек протоколов (v0.8.1)** | сломанный модуль протокола откатывается ТОЛЬКО клиентом (3 неудачи → rrp1, с записью в журнал); сервер не откатывается никогда — анти-цикл при рассинхроне обновлений и заморозке модулей. |
| **Апдейтер (v0.8.1)** | APK перед установкой сверяется с SHA256SUMS релиза; несовпадение — установка отменяется и логируется. |
| **API Mask (v0.8.2)** | фоновый шум камуфляжа ходит ТОЛЬКО внутри туннеля (ноль внешних хостов); суточный бюджет из манифеста; байты шума учитываются в счётчике трафика (лимит — король); каждый обмен честно пишется в консоль; клиент шлёт NOISE только при подтверждённой сервером возможности — старые версии обеих сторон кадр не видят. Свои ~200 строк без зависимостей: готовых MIT-библиотек маскировки под API-профиль нет, тянуть чужой мок-сервер ради этого — зависимостный кошмар. |
| **UX-канон GUI (v0.8.2)** | любая вкладка APK скроллится (портрет/ландшафт/крупные шрифты); консоль обновлений — тот же компонент, что на главной; журнал обновлений — на языке приложения; никаких «пустых полей» и пояснений-скобок в названиях настроек. |
| **Governor без шелла (v0.8.3)** | distroless-образ не содержит busybox/интерпретаторов: рестарт-губернатор — подкоманда самого бинаря (`reverseray governor`); CI docker-джоба обязана поднять контейнер с родным entrypoint и дождаться healthy. |
| **Слои модулей (v0.9.1 канон-верификация)** | новый протокол/модуль в манифесте подхватывается сервером (rrp.SetRegistry, syncer: apply/dedup/no-downgrade/мусор не применяется) и старым тонким движком APK (applyRegistryFull: id/метка/версия; движок остаётся на rrp1, мусор → rrp1, смена только через PROBE-валидацию). Тесты обеих сторон + modules_check.py — релиз движка и релиз манифеста независимы |
| **Многоязычность (v0.8.3)** | дефолт-ресурсы (values/) — EN (фолбэк), RU — values-ru; выбор языка в настройках (system/ru/en) применяется к Activity, сервису, уведомлениям и логам ядра без перезапуска; core-сообщения — типизированный каталог `Msgs` (Msg(en, ru=null) → EN); НОВЫЙ код обязан добавлять строки в ресурсы/каталог — гейт-тесты StringsParityTest/StringsGateTest падают перед деплоем и печатают, какой язык/какие поля пропущены. |

  — вызовы гвардятся `Build.VERSION.SDK_INT`; полный паритет UX на 14–20 —
  в бэклоге, приоритет низкий.
- Эмуляторные (instrumentation) тесты APK в CI — бэклог v1.0.
- cosign-подписи релизов + SBOM для APK — бэклог v1.0.
- ~~Битая mermaid-диаграмма на главной (точка с запятой в подписи ребра)~~ —
  исправлено в v0.8.2 (канон: диаграммы проверяются рендером перед пушем).

## Спидтест-методика (v0.9.2)

Измеримая база throughput (вкладка «Главная» → «Спидтест», cloudflare 25 МБ):

1. Прогон: 3 запуска подряд на стабильном линке, берём **медиану**.
2. Фиксируем: download Mbps, up Mbps, RTT (из PONG) и окно графика (avg/peak).
3. Регрессия не ниже baseline предыдущего релиза −10%; адаптивный keepalive
   (20–55 с из RTT) не должен создавать шум в фоновом трафике.
4. Окна по умолчанию (512 КБ → 4 МБ max) достаточны для 100 Мбит/с при
   RTT ≤ 100 мс — менять без замеров запрещено.

## Релизы

1. Тег `vX.Y.Z` → `release.yml`.
2. Стадии: test → build-binaries (amd64/arm64/armv7) → docker (multi-arch,
   SBOM/provenance) → build-apk (подпись) → publish (SHA256SUMS + Release,
   тело из CHANGELOG).
3. **Версионирование**: SemVer; versionCode в `android/app/build.gradle.kts`
   увеличивается на каждый релиз.
4. **Деплой-эквивалент прод-машины**: путь
   `/portainer/Files/AppData/Config/reverseray/reverseray`.
5. Откат: предыдущий digest из `deploy/digests.yaml`.
6. Автообновление контейнера запрещено; обновления — только вручную или
   автопилотом `deploy/rr.sh` (создаёт `./reverseray/` относительно текущего
   каталога, решает установка/обновление, печатает строку подключения;
   `--reset` — обнулить состояние).
7. **Скриншот-роботы (v0.9.1+, асинхронно после релиза):** отдельный
   workflow `screenshot.yml` по `workflow_run` Release=success — две
   параллельные джобы (APK с эмулятора, веб-панель из ОПУБЛИКОВАННОГО
   образа, healthy-ожидание 120 с) + commit-джоба кладёт
   `assets/brand/screenshot.png` и `assets/brand/web.png` в README
   (branch: main, rebase). Любой фейл не валит CI/Release — артефакт-диагностика.
8. Скорость релиза (v0.7): паблиш берёт артефакты `build-binaries` (без
   пересборки), Go-тест+coverage одним прогоном, кэш Gradle в CI.

## Тестовые матрицы

- **Go**: unit + E2E (fake-phone) + hostile-environment (`evilclient_test.go`)
  — запускаются в каждом PR и релизе.
- **Android**: 187 unit (Robolectric API 21/31, evil-сервер, QR, SSRF, тайминги,
  канон HELLO/AUTH, бронепарсер rrp://, согласование протоколов, PROBE-кадры);
  JVM-изоляция (`forkEvery=1`) обязательна.
- **Ассеты**: детерминизм, размеры, синхронность лендинг-копий.

## Диагностика

- Сервер: `RR_DEBUG_LOG=1` — debug-логи в тестах; admin `/metrics` — метрики.
- Клиент: кнопка «Журнал» — копируемая история ошибок.
- Артефакт `android-test-reports` в CI (always) — XML-отчёты.

## Секреты

- `RR_KEYSTORE*` (GitHub Secrets) — личная подпись APK; по умолчанию
  используется репозиторный ключ.
- Deploy key — только gh-pages/теги; ротация 12 мес.
- В репо секретов нет (gitleaks в CI).
