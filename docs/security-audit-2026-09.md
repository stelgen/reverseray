# Аудит безопасности — сентябрь 2026

Внутренний аудит протокола RRP/1, сервера и Android-клиента перед публичным
релизом 0.2.1. Ниже — найденные проблемы и их статус. Все пункты закрыты,
за отмеченными исключениями.

## Критичные (исправлены)

| # | Область | Проблема | Исправление |
|---|---|---|---|
| 1 | Android | Краш при запуске интерфейса на Android 14+: приёмник broadcasts регистрировался с флагом `RECEIVER_NOT_EXPORTED` без объявления соответствующего permission | Permission объявлен в манифесте; регистрация разделена по версии API |
| 2 | Протокол | Обход SSRF-защиты через DNS-rebinding: проверка выполнялась только по имени хоста, а фактический адрес мог оказаться приватным | Адрес резолвится клиентом, каждый полученный адрес проверяется по байтам до подключения |
| 3 | Клиент | `CompletableFuture` недоступен на API < 24 при minSdk 14 | Заменён на собственную реализацию на `CountDownLatch` |
| 4 | Клиент | `Notification.Builder#build()` вызывался без проверки версии — краш на Android 4.x | Гейт по API 16, для 14–15 — `getNotification()` |
| 5 | Сервер | Отладочный HTTP-сервер (pprof) поднимался без таймаутов | Явные Read/Write/Idle таймауты |
| 6 | Сборка | Переполнение целочисленной константы при кросс-компиляции под armv7 | Безопасное сравнение через uint64; сборка проверяется для всех архитектур |

## Существенные (исправлены)

- Отсутствие таймаута на ожидании окна flow-control: при остановке сервера
  relay-потоки оставались заблокированными. Ожидание ограничено 30 секундами.
- Остановка сервиса ждала таймаутов рукопожатия (до 20 секунд); активные
  подключения теперь закрываются принудительно.
- Состояние списка подключений изменялось из нескольких потоков без
  синхронизации — добавлены синхронизированные секции.
- Дублирование реализации SSRF-защиты в двух файлах; версия, использующая
  DNS-резолв, удалена — осталась работа по строкам и байтам без сетевых вызовов.
- В тестовом клиенте (`fakephone`) отключены TLS session tickets: проверка
  SPKI-pin обязана выполняться на каждом рукопожатии.

## Принятые риски (документированы)

- `gosec` G104 (LOW, 36 шт.): необработанные ошибки закрытия/логирования —
  стандартный шум для сервисного кода, критичность низкая.
- `gosec` G304 (MEDIUM, 8 шт.): чтение файлов по пути из конфигурации —
  это штатное поведение сервиса (файлы токенов/состояния).
- Подавления `#nosec` в энкодере кадров обоснованы лимитами протокола
  (DATA ≤ 64 КБ, управляющие кадры ≤ 4 КБ) и фаззинг-тестами.

## Ограничения автоматизации

- Unit-тесты клиента выполняются на Robolectric для API 21 и 31; для
  Android 4.x–5.x предусмотрен ручной smoke-чеклист (Robolectric не
  поддерживает эти уровни API).
- Аппаратное ускорение эмулятора недоступно в CI-окружении — инструментальные
  тесты на реальных устройствах выполняются вручную.
