# Аудит безопасности v0.8 — buffer overflow / инъекции / WAN-стойкость

Дата: 2026-10-08 · Объект: `server/` (Go 1.27) + `android/` (Kotlin) на момент
коммитов v0.8 · Метод: ручной разбор + фаззинг-стиль тесты + CI-роботы.

## 1. Сводка вердиктов

| Класс угрозы | Вердикт до v0.8 | Что сделано в v0.8 |
|---|---|---|
| Переполнение буферов | Память безопасна (Go/Kotlin bounds-check), но была точка неограниченного чтения заголовков WS | `wsMaxHeader` 8КБ (было), `wsMaxMessage` 1МБ — оставлено; добавлены лимиты на парсеры манифеста (512КБ cap) и явные проверки длин |
| Инъекции в админ-API | device name фильтровался точечно | recover-гварды на ВСЕ обработчики, security-заголовки, 500 без деталей |
| Скептицизм сканера | сервер отвечал TLS-alert'ами на мусор — пал «есть что-то на порту» | **hardening gate**: первый байт ≠ 0x16 → tarpit + тишина (0 байт) |
| Флуд/автоматизированный скан | rate-limit рукопожатий (было) | + глобальный/per-IP лимиты параллельных соединений (`RR_HARDENING_*`) |
| Slowloris | дедлайны только на TLS-фазе | 30 с на первый запрос инбокса; 15 с на KEY-обмен |
| Крипто payload'а | payload открыт внутри TLS (ок для модели) | mtproto2: канон MTProto 2.0 поверх приватного хендшейка |
| Телеметрия/внешние вызовы | «нет» по коду, но не проверялось CI | **privacy-audit робот**: белый список хостов, маркеры телеметрии, приватные IP/токены в доках |

## 2. Buffer overflow / memory safety (подробно)

Go и Kotlin — языки с проверкой границ; классический переполнение буфера
невозможен. Риски смещены в «ложные» переполнения — аллокации на данных
злоумышленника. Разбор каждой поверхности:

| Поверхность | Ограничение | Тест |
|---|---|---|
| RRP-кадры | `MaxDataPayload` 64КБ / `MaxControlPayload` 4КБ, лимит по типу | `frame_test`, evil-suite |
| WS-фреймы | `wsMaxMessage` 1 МБ, header ≤ 8КБ, handshake TTL 10 с | `ws_test` |
| HELLO/AUTH JSON | control-лимит 4КБ; `device ≤ 64`; FlexString-толерантность | `TestHandshakeToleratesApk073Format` |
| SOCKS5/HTTP инбокс | домен ≤ 255, фиксированные чтения `io.ReadFull`, `http.ReadRequest` (net/http парсер) | `mixed_test`, `udp_test` |
| UDP-конверты | `DecodeUdpData` — строгие проверки длин, cut по границам | `frame_test` |
| Манифест модулей | cap 512КБ при скачивании; `NormalizeID` [a-z0-9]{1,16}; дубликаты отвергнуты | `modules_test` (Go) / `ModulesTest` (Kotlin) / CI `modules` |
| MTProto-конверт | len(msg) ≤ len(body), паддинг 12..1024, key_id constant-time | `mtproto_test`, KAT, tamper-тест |
| Списки сессий/стримов | MaxStreams 256..1024, DeviceBudget 16МБ, inQ cap 1МБ/стрим | session-тесты |

**Вердикт:** уязвимых к переполнению поверхностей нет; большие аллокации
ограничены константами до выделения (`make([]byte, n)` после проверки n).

## 3. Инъекции

- **SQL**: БД нет — N/A.
- **Командная строка**: внешние процессы не запускаются — N/A.
- **HTTP-инъекции в plain-proxy**: `outReq.Write(dst)` — заголовки парсятся
  net/http (CRLF в значениях отвергается), `Proxy-Authorization` удаляется,
  `Connection: close` ставится принудительно.
- **Path traversal**: `enroll`/`reset-state` — пути конструируются из
  флагов админа; admin `/devices/kick` отклоняет `..`/`/`.
- **JSON-инъекции в логи**: логи redact'ятся по умолчанию; device —
  `[a-z0-9-]` (токен устройства) не попадает в shell/файлы.
- **Манифест-инъекции**: «политика» типизирована, probe-цель валидируется
  `host:port`, dns-имена — только строки; мусорный манифест не применяется.

## 4. WAN-стойкость (новое в v0.8)

- **Скрытие сервиса**: единственный ответ сканеру — SYN-ACK ядра. На
  уровне приложения: peek первого байта; не TLS → tarpit (задержка
  `RR_HARDENING_TARPIT_SEC`, по умолчанию 3 с) → тихое закрытие. Тесты
  `TestWANScanSilent` (HTTP/нулевые/PING-пробники — ноль байт ответа).
- **Дроссель**: `RR_HARDENING_MAX_CONNS` (4096) и `RR_HARDENING_PER_IP_CONNS`
  (32) — автоматизированный скан не съест fd/память; события в метриках
  без IP (приватность).
- **ICMP/SYN**: отвечает ядро хоста — рецепт iptables в SECURITY.md.
- **TLS-фаза**: MinVersion 1.3, ALPN обязателен (кроме legacy no-ALPN
  клиентов на BC), handshake deadline 15 с; ошибки не логируются наружу.

## 5. mtproto2 — крипторевизия

- Параметры: официальный dh_prime Telegram; тест простоты p и (p−1)/2
  (`TestTelegramDHPrimeIsSafePrime`), p mod 3 = 2 → g=3 канон.
- Валидация долей по guidelines (1 < g < p−1; [2^1984, p−2^1984]) — обе
  стороны; клиент дополнительно сверяет p байт-в-байт (anti-logjam).
- KDF — канон 2.0 (msg_key_large = SHA256(auth_key[88+x:120+x]‖pt)); ключи
  AES-256-IGE по таблице 2.0; IGE реализован поверх ECB одинаково в Go и
  Kotlin (без JCE-провайдер-магии) — кросс-языковой KAT.
- Целостность: msg_key воспроизводится из расшифрованного тела; tamper-тест
  (модификация шифротекста → отказ); чужой key_id → отказ (constant-time).
- Replay: msg_id монотонные счётчики по направлениям с канонической
  чётностью; salt/session_id привязаны к RRP-сессии (nonce одноразовый на
  уровне приватного хендшейка).
