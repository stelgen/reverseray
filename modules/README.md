# Модули (общая база APK ↔ сервер)

**Канон v0.8**: APK — тонкий движок (как ПО POS-терминала), вся общая логика
живёт в обновляемых модулях. Сервер и приложение парсят **один и тот же**
манифест `modules/modules.json` и оркестрируют его одинаково — поэтому
клиент и сервер никогда не расходятся во мнении о поддерживаемых
протоколах и правилах.

## Что здесь

| Файл | Назначение |
|---|---|
| `modules.json` | манифест: реестр протоколов + общая политика |

## Схема манифеста (schema 1)

```jsonc
{
  "schema": 1,                       // только 1
  "version": "0.8.0",                // семвер манифеста
  "updated": "2026-10-08",
  "protocols": [                     // реестр протоколов туннеля
    { "id": "rrp1", "name": "RRP/1", "default": true },  // rrp1 обязателен
    { "id": "mtproto2", "name": "MTProto/2" },           // enabled по умолчанию
    { "id": "будущий", "enabled": false }                // можно выключать
  ],
  "policy": {
    "probe_default_target": "1.1.1.1:443",           // PROBE-валидация (APK)
    "dns_probe_names": ["o-o.myaddr.l.google.com"]   // «кто реально резолвит» (APK)
  }
}
```

Правила (проверяются тестами на обеих сторонах):

- `schema` ≠ 1 → манифест отвергается;
- `id` протокола — `[a-z0-9]{1,16}`;
- `rrp1` присутствует всегда (фундамент) — манифест без него отвергается;
- `enabled: false` — протокол исключается из согласования;
- мусорный манифест **никогда не применяется**: работает предыдущий или
  встроенный реестр (фоллбек в стабильный `rrp1`).

## Дисциплина обновления

- **APK**: вкладка «Обновление» + авто-режим — качает манифест с GitHub,
  сверяет версию/хеш, применяет реестр без переустановки APK;
- **Сервер**: env `RR_MODULES_URL` (по умолчанию raw.githubusercontent main),
  `RR_MODULES_AUTO` (1), `RR_MODULES_CHECK_HOURS` (24);
  качает ТОЛЬКО при изменении версии или sha256, пишет в
  `state/modules.json`, применяет реестр на горячую;
- даунгрейд запрещён (CDN-гонка не может откатить реестр).

## Новый протокол в 3 шага

1. Реализация: Go `server/internal/...` + Kotlin `core/...` (код едет
   в APK/бинарнике — модуль несёт правила, а не исполняемый код);
2. Строка в `modules.json` (+ тесты согласования с обеих сторон);
3. Релиз: старые APK/серверы подхватывают протокол из манифеста при
   следующем чеке и договариваются о нём в рукопожатии; если сторона
   ещё не знает протокол — автоматический фоллбек на общий.
